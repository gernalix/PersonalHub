# PersonalHub operating rules

- Follow the governing MegaVault protocol before project work.
- Treat intermediate failures as recoverable evidence, not terminal task outcomes. Diagnose the smallest concrete cause, apply the minimum safe in-scope fix, rerun the failed leaf gate, then resume the original goal automatically. A compile/test failure, remote advance, or unrelated dirty work is not by itself BLOCKED. Use BLOCKED only for a hard external/user-action blocker or unsafe ambiguity; use FAIL only after reasonable in-scope recovery is exhausted. Never turn recovery into repo-wide audit, refactor, cleanup, or repeated equivalent retries.
- For code localization, search `.codex/CODE_MAP.tsv` first using the user's feature/concept/alias and open only the matched primary/related paths. Treat the map as routing hints, not source of truth. Use narrow symbol/path search next and repo-wide search only when the indexed targets are missing, stale, or insufficient.
- Before the first Gradle invocation after changing a public Kotlin type/method, DAO API, constructor shape, or Room entity/schema-facing API, run `python3 tools/android_consumer_preflight.py scan --symbol '<exact literal>' ...` for every changed API/symbol that can have consumers. The helper deliberately emits only paths/modules and fails boundedly when a symbol is too broad; do not replace it with repo-wide `rg -n` content dumps. Read only the returned consumer files/blocks and update every affected call site first. For removed/renamed literals, require `python3 tools/android_consumer_preflight.py gate --forbid '<old literal>' ...` to PASS before Gradle. When a constructor/method remains valid but its shape changed, rescan that exact constructor/method and inspect every returned consumer instead of using the obsolete-symbol gate. Only after consumer closure run one quiet compile gate for the highest affected consumer module (`./gradlew :<module>:compileDebugKotlin --quiet --console=plain` when available), then proceed to targeted tests; a compile failure must drive only a leaf correction from the compiler evidence, never a new broad discovery sweep.
- Keep `.codex/CODE_MAP.tsv` compact and semantic: update only rows whose feature ownership, important symbol, path, or targeted test materially changed; never turn it into an exhaustive class/function inventory.
- Treat every `:feature:*` module as an implementation capsule. The `:app` composition root may import feature code only through the direct `.api` or `.hub` package; nested implementation packages remain private. Features must not depend on or directly import another feature implementation; contracts must remain implementation-free; core must never depend on a feature. Each feature owns its Android Activities/receivers/providers/services and public shortcut alias in its own manifest; the host manifest must never declare a feature implementation component or embed private feature Activity class names. Run `./gradlew checkArchitectureBoundaries` after any change to module wiring, public integration entrypoints, persistence ownership, manifests, or feature package boundaries.
- PersonalHub work is serialized by default. Once a task enters device QA/release, do not absorb unrelated commits that arrive on `origin/main`; treat concurrent PersonalHub work as a blocker unless the prompt explicitly declares the work compatible. Re-fetch before the final integration gate, not repeatedly during stable QA.
- Before entering implementation, QA, or release for a PersonalHub roadmap task, acquire the local lease with `python3 tools/personalhub_task_lock.py acquire --prompt-id <PROMPT_ID>`. A second acquire must be reported as BLOCKED, not waited on. Release it explicitly with `python3 tools/personalhub_task_lock.py release --prompt-id <PROMPT_ID>` after PASS, BLOCKED, or FAIL. Stale recovery is allowed only through the tool's TTL checks, never by manually deleting a live lock.
- For emulator-capable Android QA, use `python3 tools/android_emulator_control.py status|start|wait|stop`; use `smoke --timeout 90` only for emulator-infrastructure validation. See `docs/ANDROID_EMULATOR.md`. A successful `start`/`wait` returns the canonical live `target.serial`. The facade resolves the canonical `Pixel_8a` through the existing preflight, prevents unrelated/offline AVD rows from becoming the canonical target, cleans only processes created by a failed start and keeps a final-stop budget. Do not duplicate emulator/ADB discovery unless the facade reports a blocker. The older `android_target_preflight.py` CLI remains compatibility-only; treat older project/roadmap text that invokes it directly as stale unless the task explicitly tests the low-level preflight itself.
- Physical-device androidTests must keep their physical-device safety guards. Never weaken a Pixel/non-generic/non-SDK guard just to make the same test run on the canonical emulator. When acceptance requires emulator QA for behavior previously covered only by a physical-device test, add or use a narrowly scoped emulator-safe test instead; keep physical-only tests physical-only.
- For a physical-Pixel APK install, use `python3 tools/android_pixel_apk.py install` after the required build. It resolves the exact debug artifact from Gradle `output-metadata.json`, resolves the physical Pixel through the existing preflight library, and always scopes `adb install -r` to that serial. Do not guess `app-debug.apk`, parse `adb devices` manually, or attempt an unscoped install first.
- For Pixel Perfetto queries, use `python3 tools/android_perfetto_query.py TRACE --query-file QUERY.sql` (or `--query` for short SQL) when the trace path is already known. When the task only needs to reuse the newest existing PersonalHub trace, use `python3 tools/android_perfetto_query.py --latest-trace --query '…'`; the helper searches the known runtime roots and already defaults to the canonical benchmark `trace_processor_shell_aarch64`. Do not probe the processor with `--help`, `rg --files`, `find`, `which`, or manual ADB first; fall back to manual discovery only if the helper reports a concrete blocker.
- For Android UI inspection during QA, use `python3 tools/android_ui_summary.py --serial <serial>` instead of printing raw `uiautomator` XML. When checking a known label/value/error, prefer `--match '<regex>'` so only relevant semantic nodes are emitted. Print the full XML only if the compact helper fails or cannot provide evidence required by the task; do not emit repeated full-tree dumps for routine navigation.
- For emulator-infrastructure unit verification, run only `PYTHONDONTWRITEBYTECODE=1 python3 tools/test_android_emulator_stack.py`. It already runs the historical preflight, regression and facade suites and rejects tracked Python cache artifacts. After PASS, do not rerun those component suites individually. If real host validation is required, add exactly one facade `smoke --timeout 90`; its structured result replaces manual ADB/process checks. For emulator-related tasks, route directly to `tools/android_emulator_control.py`, `tools/android_target_preflight.py`, `tools/test_android_emulator_stack.py` and `docs/ANDROID_EMULATOR.md` instead of doing repo-wide discovery.
- `version.txt` is the sole source of truth for both Android `versionCode` and `versionName`. Every future PersonalHub development prompt increments its integer exactly once by `+1`; never derive it from time, Git, or generated source.
- The Home title is always `PersonalHub`; render only the version number, small and discreet, at the bottom-right.
- The default final delivery artifact is the canonically signed debug APK named exactly `<version>.apk` (for example `3.apk`) unless the task explicitly requires a release artifact. Do not minify, ABI-split, post-process or re-sign an APK solely to satisfy a transport-size limit; fix/use the delivery transport instead.
- After the final artifact passes its required gates, treat it as immutable: install that exact file on the Pixel. If it is at or below 50 MiB, send that exact file through the configured Telegram cloud Bot API path. If it is larger, publish it as the current asset of the stable `personalhub-dev-apk` GitHub prerelease and send the release link through Telegram. PersonalHub is private, so that link requires GitHub authentication unless repository visibility changes. A transport failure must not trigger an alternate rebuild that changes the tested artifact.
- Keep the single `personalhub.db`, atomic validated import/export, and crash rollback. Never reintroduce `MigrationActivity`, `:core:migration`, legacy feature databases, or migration-map code.
- Pre-import backups may be removed only when no valid import-pending marker references them. Successful verified imports and startup recovery must clean obsolete pre-import backups.
- Before the first final APK/build/delivery for a change that adds or alters UI, perform one focused source/UI gate for newly exposed values: raw epoch milliseconds, database IDs/UUIDs, cursors, and backend-only encodings must never be user-visible unless the feature explicitly requires them.
- For terminal Git writes in any repository required by a PersonalHub task, resolve the repository's current canonical/default branch from remote state and push that branch; never assume or hardcode `main` versus `master`.
