**Scope:** preventive QA and tooling after 193828; no new production feature,
no APK delivery and no NV increment. Never test on the production Pixel by
default. No C2/C3.

## Implemented checks

- The existing synthetic `HistoryAndPatchReviewDeviceTest` seeds 719 intakes
  and 1,100 newer mutations and exercises the scoped/global UI. It now measures
  page 50→100 and fails if the emulator takes at least 12 seconds.
- CI reinstalls the **same** `.qa` APK on that populated clone, preserving its
  data and triggering the real package-replacement lifecycle. Two
  `HistoryUpgradeDeviceTest` cases verify the Timer restore receiver does not
  block the main thread under a held `DatabaseGate`, and History still finds
  the seeded records and paginates after update. Emulator logcat is checked for
  package-specific ANRs. The real `com.gernalix.personalhub` package is never
  the instrumentation target.
- History publishes Compose test tags as accessibility resource IDs, avoiding
  unreliable text/position selectors. `PHHistoryUndoPerf` logs only the
  elapsed time of a **single expanded** Git Undo preview, and adds a Perfetto
  trace section `PH.HistoryGitUndoPreview`. No Git event IDs or sensitive
  contents are logged. The existing unit test guarantees zero Git sandbox
  previews for 50 closed rows.
- GitHub Actions now uses `gradle/actions/setup-gradle@v4` caching without
  duplicating the setup-java Gradle cache; unit checks use bounded
  `--parallel --max-workers=2 --build-cache`. Required lint, architecture,
  unit, and instrumentation checks are retained. Workflow path triggers include
  the instrumentation script and the current v23→v24 migration safety tools.
- `tools/android_paired_cutover_v24.py` centralizes *future, explicitly
  authorized* schema-23→24 paired transitions (freeze, fresh coherent SQLite
  snapshot, validated migration, hash guard, staged publication, rollback
  APK+DB and fail-closed aborts); host-only fake-device tests exercise the
  failure paths. It is not appropriate for a device already on schema 24,
  and reports `PAIR_INSTALLED_QA_PENDING`, not final release PASS.

## Explicit limitations and release gates

- No physical-Pixel production-data run, APK delivery or schema migration is
  authorized by this maintenance task. Current primary device already uses
  schema 24; this specialized v23→v24 cutover script was host-simulated only.
- Authentic Git Undo sandbox latency requires a securely configured Git QA
  environment; do not copy real Git credentials into clones. The new trace
  provides instrumentation for that future controlled measurement; JVM
  closed-row proof does not substitute for the authenticated end-to-end case.
- A future real paired cutover still requires user-exclusive Pixel pre/post
  Fedora+Telegram notices, verified rollback inventory, native QA, database/ID
  and remote Git-export readback, and exact immutable-APK delivery. Never infer
  release success from `PAIR_INSTALLED_QA_PENDING`.
- CI speed improvement must be evaluated from **actual next PR timing**; no
  unmeasured wall-time reduction is claimed.
